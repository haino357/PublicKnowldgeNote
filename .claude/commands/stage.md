# /stage — ステージング + コミットメッセージ提案

`git add` でステージングし、ステージ内容に対応したコミットメッセージ案を**同じ応答内で**提示する。**実際の `git commit` は実行しない**（ユーザー承認後に別途実行）。

WorkTaskBoard の `/stage` を、PublicKnowldgeNote 向けに調整したもの。

## 動作仕様

### 1. 引数

- **引数なし**：`git status` で全変更を確認 → 関連性でグルーピングして「どれをステージするか」候補を提示 → 承認後にステージ
- **引数あり（パス指定）**：指定されたパス／パターンを `git add` でステージ
- **`--all`**：機密ファイル（後述）を除外して全変更をステージ

### 2. 処理フロー

1. 並列実行で現状確認：
   - `git status`（変更ファイル一覧）
   - `git diff`（未ステージ差分）
   - `git diff --staged`（既ステージ差分）
   - `git log -5 --oneline`（過去のコミットスタイル参照）
2. 実行前から既にステージ済みの変更があれば、その一覧を示す。**既存のステージ状態は維持し、外さない**（`AGENTS.md` の「作業前からある変更とステージ状態を維持する」に従う）
3. ステージ対象を確定（引数あり：そのまま／引数なし：候補提示 → 承認）
4. `git add <paths>` を実行
5. `git diff --staged --stat` でステージ結果を要約表示
6. **コミットメッセージ案を 1〜3 候補提示**：
   - **Conventional Commits 接頭辞を必ず付与する**（下記「3. 接頭辞の判定」参照）
   - 接頭辞の後は **日本語の descriptive な件名**、短く（70 文字以内目安）、必要なら本文で詳細
   - 件名のフォーマット：`<type>: <subject>` または `<type>(<scope>): <subject>`
   - 末尾に `Co-Authored-By: <実行中のClaudeのモデル名> <noreply@anthropic.com>` を入れる（モデル名は固定せず、実行時のセッションのものを使う）
   - 候補は「簡潔版 / scope 付き版 / 情報量増し版（本文あり）」のような切り口で出す
   - 関連性の薄い変更が混ざっている場合は分割提案も併記

### 3. 接頭辞の判定

ステージ内容から決める。**複数カテゴリにまたがる場合は dominant change（主たる変更）で選ぶ**。

| 接頭辞 | 適用条件 | このリポジトリでの例 |
|--------|---------|------------|
| `feat:` | 公開ページ・記事機能・新しい仕組みの追加 | `docs/<page-slug>/index.html` の新規公開、記事の公開状態への更新 |
| `fix:` | 誤り・リンク切れ・表示崩れの修正 | Basesの抽出条件の修正、記事内リンクの修正 |
| `docs:` | 記事・技術ノートの追加・更新 | `Articel/`、`Flutter/`、`VSCode/`、`Git/`、`mobile/`、`README.md`、`AGENTS.md` |
| `refactor:` | 内容は同等のままの構造変更 | カテゴリの再編、記事管理方法の変更 |
| `chore:` | 設定系・メタファイル・ハウスキーピング | `.claude/`、`.gitignore` |
| `style:` | フロントマター整形・空行調整など意味を変えない整形 | YAMLプロパティ順の統一、表の整形 |

**scope（任意）**：`<type>(<scope>): <subject>` 形式で付けられる場合は付ける。このリポジトリでよく使う scope：

- `docs(article)`, `feat(article)` — `Articel/` の記事
- `feat(pages)`, `feat(docs)` — `docs/` 配下の公開Webページ
- `docs(vscode)`, `docs(obsidian)`, `docs(readme)` — 分野別の技術ノート・README
- `fix(bases)` — `.base` ファイル
- `chore(claude)` — `.claude/` 配下

**判定の例**：

| ステージ内容 | 接頭辞 |
|------------|-------|
| `Articel/` に下書き記事を追加 | `docs(article):` |
| 記事を公開状態に更新しサムネイルを追加 | `feat(article):` |
| `docs/<page-slug>/index.html` を新規追加 | `feat(pages):` |
| `.base` の抽出条件の誤りを修正 | `fix(bases):` |
| `VSCode/` の設定メモを更新 | `docs(vscode):` |
| `.claude/commands/stage.md` を追加 | `chore(claude):` |

### 4. 機密ファイルの自動除外

以下のパターンに一致するファイルはステージ対象外（警告のみ表示）：

- `.env`, `.env.*`
- `*.key`, `*.pem`, `*.p12`
- `credentials*`, `secret*`, `token*`
- `.aws/`, `.ssh/` 配下

### 5. 制約

- **`git commit` は絶対に実行しない**。このコマンドの責務はステージ + 提案まで
- **`git push` も実行しない**
- **`--no-verify` などフックスキップは絶対に提案しない**
- 実行前から既にステージ済みの変更は外さない。分割したい場合は `git restore --staged <path>` を提案するだけにする
- 機密ファイルが検出された場合は強く警告し、ユーザーが明示的に許可するまでステージしない

## 使用例

```
/stage
→ 変更全体を確認 → 関連グループ提示 → 承認 → ステージ + メッセージ案

/stage Articel/記事タイトル.md
→ 1 ファイルをステージ → メッセージ案

/stage --all
→ 機密ファイル除外して全変更をステージ → メッセージ案
```

## 関連

- **`/commitmsg`** — 既ステージ済みの内容に対するメッセージ提案のみを行う下位コマンド。接頭辞の判定表は共通
- `AGENTS.md` — 作業前の変更・ステージ状態の維持、事前承認が必要な操作
- このコマンドは「コミット直前のワークフロー」を担当。実際の `git commit` 実行は別途ユーザーが指示
