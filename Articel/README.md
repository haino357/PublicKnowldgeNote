# Articel 記事管理ルール

このディレクトリは、公開記事のアイデア、下書き、投稿待ち、公開済み原稿を管理する場所です。

## 基本方針

- 記事の進捗は、フォルダではなくFrontmatterの `status` で管理する
- `未完成`・`投稿済`など、進捗を表すサブディレクトリは作らない
- ステータスを変更しても、ファイルの移動や改名は行わない
- 元情報へのリンクや出典を残し、あとから事実確認できる状態にする
- 公開後も原稿を消さず、再利用できる成果物として保管する

## ステータス

| status      | 状態           | 完了条件                 | 次の状態        |
| ----------- | ------------ | -------------------- | ----------- |
| `idea`      | タイトルや着想だけがある | 主張と想定読者が決まっている       | `draft`     |
| `draft`     | 執筆・構成整理中     | 本文が一通り完成している         | `ready`     |
| `ready`     | 推敲済みで投稿できる   | 公開先を決め、最終確認が終わっている   | `published` |
| `published` | 外部サービスへ公開済み  | 投稿日・投稿先・公開URLを記録している | 維持          |

通常は `idea` → `draft` → `ready` → `published` の順で進めます。

公開後に誤字修正や加筆を行っても、`status` は `published` のまま維持します。公開を取り下げた場合も、公開履歴を消さず、本文か別プロパティに理由を残します。

## Frontmatter

新規記事は次の形式を基本とします。

```yaml
---
created: YYYY-MM-DDTHH:mm:ss
tags:
  - タグ
status: idea
post date:
投稿先:
投稿先URL:
---
```

### 必須項目

| プロパティ | 必須になる状態 | 記入内容 |
|---|---|---|
| `created` | 全状態 | ノートを作成した日時 |
| `tags` | 全状態 | 記事のテーマ。検索・関連付けに使う |
| `status` | 全状態 | `idea`・`draft`・`ready`・`published`のいずれか |
| `post date` | `published` | `YYYY-MM-DD`形式の投稿日 |
| `投稿先` | `published` | `note`・`はてなブログ`・`Qiita`・`Zenn`など |
| `投稿先URL` | `published` | 公開記事のURL |

既存記事で項目が不足している場合は、一括して推測で埋めず、次にその記事を編集するときに確認して補完します。

## 記事作成から公開まで

1. 記事のタイトルでMarkdownファイルを作り、`status: idea`にする
2. 主張、想定読者、書く理由を決めたら`status: draft`にする
3. 本文を書き、出典・リンク・画像・誤字を確認する
4. そのまま投稿できる状態になったら`status: ready`にする
5. 外部サービスへ投稿する
6. `status: published`へ変更し、`post date`・`投稿先`・`投稿先URL`を記録する
7. 必要に応じて、`PublicKnowldgeNote/README.md`の代表記事一覧へ追加する

## `ready`へ変更する前の確認

- [ ] タイトルと本文の主張が一致している
- [ ] 想定読者に必要な前提が書かれている
- [ ] 同じ説明を繰り返していない
- [ ] 未記入の見出し、仮テキスト、不要なコメントが残っていない
- [ ] 数値、引用、固有名詞、外部リンクを確認した
- [ ] 画像とObsidianの埋め込みが解決できる
- [ ] 個人情報、認証情報、非公開の業務情報を含んでいない

## ファイルと画像

- 原則として、記事は `Articel` 直下に `記事タイトル.md` の名前で置く
- 記事の状態をファイル名へ入れない
- 複数記事で共有する画像は `Articel/picture` に置く
- 一つの記事だけで使う画像やSVGが多い場合は、記事と同名のディレクトリに原稿と素材をまとめてよい
- 画像の移動時は、記事内の埋め込みが解決することを確認する

## 執筆・出典のルール

- 既存記事の文体を優先し、無理に文量を増やさない
- 冒頭で扱う問題や書く理由を示し、最後に主張または次の行動を残す
- 外部情報を使った場合は、該当箇所の近くか記事末尾にリンクを残す
- 元になったVault内のノートがある場合は、Wikilinkで関連付ける
- 引用と自分の意見を混同せず、推測は推測と分かる形で書く
- 公開済み原稿の大幅な変更は、公開先との差分が生じることを意識する

## 定期確認

月に一度を目安に、次を確認します。

- `ready`のまま止まっている記事を投稿するか見直す
- 長期間更新していない`draft`を、継続・保留・統合のどれにするか決める
- `published`なのに投稿日・投稿先・URLがない記事を補完する
- リンク切れ、画像切れ、古くなった内容がないか確認する

> [!important] 管理の原則
> フォルダは「記事」という情報の種類を表し、`status`は記事の進捗を表します。同じ状態をフォルダとプロパティの両方で管理しません。
